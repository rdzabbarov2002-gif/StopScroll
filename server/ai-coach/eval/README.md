# Сравнение моделей для разбора записей (`/entry`)

Стенд отвечает на один вопрос: достаточно ли `gpt-5.4-nano` для разбора записей StopScroll или
экономия обходится слишком большой потерей качества. Код приложения он не меняет и в Worker не
попадает (Wrangler собирает только `src/index.ts`).

## Что внутри

- `entries.json` — 120 реалистичных записей разных типов: очень короткие, длинные, эмоциональные,
  запутанные, неоднозначные, с несколькими причинами, с нехваткой информации, автоматическое
  открытие, стресс, скука, прокрастинация, после работы, ночью, после конфликта, после прогулки,
  после хорошего и плохого дня, «сам не знаю почему», скрытые закономерности. Половина — с памятью
  пользователя (`memory.json`), половина — как у нового пользователя. У каждой записи — эталон,
  составленный заранее: главная и дополнительные причины с допустимыми формулировками, состояние,
  контекст, тип поведения, хватает ли информации, факты, которые обязан сохранить `gist`, грубые
  ошибки смысла, ожидаемые голоса за гипотезы и есть ли неочевидная связь с памятью. Записи писали
  четыре независимых автора, каждую партию проверял отдельный рецензент.
- `run.mjs` — прогоняет каждую запись через **настоящий** `/entry`: функция `handle()` Worker'а
  (те же инструкции, схема, `verbosity`, лимиты, проверка), реальный клиент OpenAI, затем разбор
  ответа кодом приложения (`parseEntryResult`). Пишет токены, задержку и ответ каждого вызова.
  По умолчанию каждая запись — 3 раза на каждой модели (видно, насколько ответы стабильны).
- `judge.mjs` — слепая попарная оценка по эталону: судья не знает, где какая модель, и оценивает
  каждую запись дважды с переставленными A/B. По каждому полю — балл 0–3, худшая ошибка (нет /
  лёгкая / серьёзная / смысл понят неправильно), влияние на долгосрочную память и потерянные в
  `gist` факты. С `--export` вместо вызова API сохраняет слепые пакеты для независимого судьи.
- `report.mjs` — отчёт `results/<имя>/report.md`: автоматические метрики, оценка судьи по полям и
  типам записей, все расхождения моделей с объяснением, отдельно `gist`, все грубые ошибки,
  измеренная цена и проекция на 100 / 1000 / 10000 пользователей, гибридные правила и итоговое
  решение по критериям, заданным в `report.mjs` **до** прогона.

## Запуск

Нужен ключ OpenAI в переменной окружения `OPENAI_API_KEY` и доступ к `api.openai.com`.

```bash
cd server/ai-coach
npm install
# 1. Ответы моделей: 120 записей × 2 модели × 3 повтора = 720 вызовов, около $1–2
node --no-warnings --import ./eval/ts-hooks.mjs eval/run.mjs --arms nano,mini --repeats 3
# 2. Слепая оценка: 240 вызовов судьи (по умолчанию gpt-5.5, effort medium), около $10–25
node --no-warnings eval/judge.mjs --pair nano,mini
# 3. Отчёт
node --no-warnings eval/report.mjs --pair nano,mini
```

Дополнительно можно сравнить `nano` с рассуждением `medium` (`--arms nano-medium`, затем
`--pair nano-medium,mini`). Прервать и продолжить можно в любой момент: готовые вызовы
пропускаются. Проверить сам конвейер без API: `run.mjs --mock` (ответы-заглушки, не результат).

## Как читать результат

- **Итого** — средний балл судьи по полям, в процентах от максимума.
- **Серьёзные ошибки** — потеряна или искажена важная деталь; **смысл понят неправильно** — запись
  понята не так (такие ошибки опаснее всего: они попадают в `gist` и дальше в память).
- Совпадение фактов `gist` по основам слов — грубая автоматическая проверка; смысловую даёт судья.
- 95% интервалы посчитаны бутстрепом по записям: при 120 записях разница меньше 3–4 п. п. может
  быть случайной.
- Судья — тоже модель OpenAI. Порядок ответов скрыт и переставляется, но одна семья моделей может
  оценивать похожие ответы мягче; для перекрёстной проверки есть `judge.mjs --export`.
