# StopScroll

Персональный AI-коуч по цифровым привычкам. Пользователь своими словами записывает, что произошло
перед тем, как захотелось открыть ленту, — ChatGPT разбирает каждую запись (причина, состояние,
ситуация, тип поведения), постепенно изучает всю историю, строит прогноз риска на сегодня,
замечает изменения, выдвигает осторожные гипотезы, изредка задаёт уточняющие вопросы и раз в
неделю предлагает маленький эксперимент. Всё это — на вкладке **AI**, без чата. Без подключённого
ChatGPT продолжает работать прежний коуч на устройстве. История хранится локально, монетизация —
через RevenueCat.

Проект собран на архитектуре шаблона [CleanStart](https://github.com/rdzabbarov2002-gif/Clean):
тот же стек, контекст + чистый редьюсер, валидация сохранённого состояния, NativeWind-компоненты.

**Стек:** Expo SDK 57 (managed, Continuous Native Generation) · React Native 0.86 · TypeScript ·
NativeWind 4 (Tailwind CSS 3) · React Navigation 7 (native stack + bottom tabs) · AsyncStorage ·
react-native-svg · `@react-native-community/slider` · RevenueCat (`react-native-purchases`) ·
`expo-notifications` · виджеты iOS через `@bacons/apple-targets` (WidgetKit) · виджеты Android
через `react-native-android-widget` · сервер AI-коуча `server/ai-coach` (Cloudflare Worker +
официальный SDK `openai`, Responses API со Structured Outputs).

## Запуск

```bash
npm install
cp .env.example .env.local   # ключи RevenueCat (можно пропустить — см. ниже)
npm start                    # QR-код для Expo Go (без виджетов и уведомлений)
npx expo run:android         # нативная сборка Android (нужен Android SDK)
npx expo run:ios             # нативная сборка iOS (нужен macOS + Xcode 16)
npm run web                  # быстрый просмотр в браузере
```

Виджеты, уведомления и покупки работают только в нативной сборке (`npx expo run:*` или
`eas build --profile preview`): папки `ios/` и `android/` не хранятся в репозитории, их генерирует
`npx expo prebuild` из `app.json`, плагинов и `targets/`.

Проверки:

```bash
npm run typecheck  # tsc --noEmit
npm run lint       # ESLint (eslint-config-expo)
npm test           # Jest: коуч, редьюсер, хранилище, статистика, аналитика, отчёт, достижения, виджеты
```

## AI-коуч (ChatGPT)

### Как это устроено

```text
запись → /entry (ChatGPT разбирает запись) → /insights (ChatGPT обновляет память и всю аналитику,
прогноз, вопрос, эксперимент) → экран AI и главная обновляются сами
в течение дня → /forecast (ChatGPT обновляет только прогноз)
```

- **Вся интерпретация — ChatGPT.** Причины, эмоции, контекст, тип поведения, закономерности,
  гипотезы, прогноз, объяснения цифр, вопросы и эксперименты формулирует модель. В приложении нет
  ни поиска ключевых слов, ни правил классификации записей.
- **Приложение только считает** (`src/ai/facts.ts`): сколько срывов, записей, побед и минут было по
  часам, дням недели, неделям и месяцам за всю историю, серии, базовые частоты («в 3 из 4 последних
  четвергов был срыв»), сэкономленное время, итоги эксперимента «до / во время». Это арифметика, а не
  анализ: так ChatGPT получает всю историю в нескольких килобайтах и не пересчитывает сотни записей
  сам (в этом языковые модели ошибаются).
- **Память.** ChatGPT каждый раз получает свою прошлую сжатую память (`summary`, датированная
  `timeline`, рекорды, гипотезы со статусом, открытые вопросы) и возвращает обновлённую — анализ не
  начинается с нуля, а долгосрочные изменения («раньше воскресенье было самым тяжёлым днём») не
  теряются. Плюс помесячная арифметика за 24 месяца. Новые записи отправляются только один раз —
  в ближайшее обновление после их появления.
- **Прогноз** — оценка ChatGPT по личной истории с опорой на базовые частоты; модель обязана
  объяснить его фактами. Это не откалиброванная статистическая модель: цифра тем надёжнее, чем
  больше истории.
- **Вопросы** — не чаще раза в три дня и только если модель считает, что ответ улучшит анализ;
  **эксперимент** — не чаще раза в неделю. Ответы и итоги экспериментов попадают в следующие анализы.
- **Ответы проверяются** (`src/ai/parse.ts`): структура и размеры; битый ответ не попадает на экран.
- **Хранение** (`src/ai/storage.ts`): отдельно от основного состояния, записи — по месяцам (UTC) в
  своих ключах AsyncStorage (каждое значение остаётся маленьким), история не обрезается; на Android
  база AsyncStorage расширена до 64 МБ (`plugins/withAsyncStorageSize.js`, по умолчанию 6 МБ). Текст
  записи — до 2000 символов. Неудачная запись на диск повторяется при следующем сохранении.
- **Удаление.** Удалённая запись исчезает с телефона; если ChatGPT её уже видел, в следующий анализ
  уходит только пометка «удалена» (дата, время, причина — без текста), чтобы модель убрала из памяти
  выводы, которые держались только на ней. Сброс или выключение во время запроса отбрасывает его ответ.
- **Расписание** (`src/ai/schedule.ts`, `src/context/AiContext.tsx`): один запрос за раз; анализ
  записи — сразу; аналитика — после новых записей и ответов, а при других изменениях (срывы, победы,
  время в ленте) — раз в день; прогноз — после новых данных (не чаще раза в 10 минут), при
  возвращении в приложение, если устарел (3 часа) или прошло его время. Ошибка — повтор через 1–2
  минуты по таймеру; нет сети, тайм-аут или перегрузка не тратят попытки, а битый ответ или ошибка
  сервера — тратят (после трёх запись ждёт «Повторить»). Одно полное обновление за проход: циклов
  запросов нет. Итог эксперимента запрашивается один раз.
- **Разрешение.** До явного согласия пользователя ничего не отправляется (требование App Store
  5.1.2(i) и GDPR); выключить и стереть данные коуча можно в Настройках.
- **Без ChatGPT** (сервер не подключён, нет согласия или сети) записи сохраняются и ждут, а на
  главной работает прежний коуч на устройстве (`src/coach`). В веб-демо без сервера вкладка AI
  показывает **помеченный** образец экрана.

### Сервер `server/ai-coach`

Ключ OpenAI нельзя класть в приложение: всё, что попадает в сборку (в том числе `EXPO_PUBLIC_*`),
можно извлечь. Поэтому между приложением и OpenAI стоит Cloudflare Worker. Он ничего не хранит
(`store: false`, без базы): память и история приходят с телефона в каждом запросе.

```bash
cd server/ai-coach
npm install
npx wrangler@4 secret put OPENAI_API_KEY
npx wrangler@4 secret put APP_TOKEN        # необязательно; то же значение — в EXPO_PUBLIC_AI_TOKEN
npm run deploy                             # URL Worker'а → EXPO_PUBLIC_AI_URL
npm run typecheck
```

Модель задаётся переменной `OPENAI_MODEL` (по умолчанию `gpt-5.4-mini` — недорогая модель со
Structured Outputs), глубина рассуждений — `OPENAI_REASONING_EFFORT` (по умолчанию `low`).
**Перед публикацией включите лимиты** в `wrangler.toml` (Workers Rate Limiting): `RATE_LIMITER` —
по IP (обойти, подменив заголовок, нельзя) и при желании `INSTALL_RATE_LIMITER` — по установке; и
задайте месячный бюджет проекта в кабинете OpenAI. `APP_TOKEN` защищает только от случайного
трафика: он виден в сборке приложения. Тело запроса ограничено по байтам до чтения. Коды ответов:
502 — непригодный ответ модели, 503/504/429 — временная недоступность (приложение ждёт и
повторяет), 500 — ошибка настройки (ключ, модель); подробности — в логах Worker (`wrangler tail`). Для веб-превью задайте переменные репозитория `AI_URL` и
`AI_TOKEN` (Settings → Secrets and variables → Actions → Variables).

**Стоимость и скорость (оценка).** Разбор записи — около 1–2 тыс. входных и до 1 тыс. выходных
токенов; обновление аналитики — 3–8 тыс. входных и 2–4 тыс. выходных; прогноз — 2–3 тыс. и до 1
тыс. При 3–5 записях в день это порядка 10–15 запросов и 50–100 тыс. токенов на пользователя в
сутки. Сколько это стоит, зависит от выбранной модели — сверьтесь с актуальными ценами на
openai.com/api/pricing. Разбор записи обычно занимает несколько секунд, полное обновление —
до 10–30 секунд; интерфейс не ждёт: запись сохраняется сразу, выводы появляются по готовности.

### Живые формулировки

Прежний коуч на устройстве может отдавать свои готовые фразы (без заметок и записей) на `/phrase`,
где ChatGPT делает их естественнее; приложение принимает новую формулировку, только если в ней те же
числа, время и дни недели (`src/coach/phrasing.ts`). Работает при подключённом сервере и разрешении.

### Прежний коуч на устройстве

`src/coach` — детерминированный разбор последних 8 недель (брифинг дня, советы, разбор недели,
ответ после срыва в Дневнике). Он остаётся как часть приложения: на главной он виден, пока
ChatGPT не подключён, а разбор недели и ответ после срыва работают всегда.

## Виджеты

Пять виджетов на iOS (`targets/widget`, SwiftUI/WidgetKit) и Android (`src/widgets`,
`react-native-android-widget`): «Сегодня» (спасено), «Серия», «Лимит» (сколько осталось),
«Прогресс дня» (кольцо) и «Полезная замена» (меняется каждые полчаса). На iOS «Сегодня», «Лимит»,
«Серия» и кольцо есть и для экрана блокировки. Приложение пишет снимок реальных цифр
(`src/widgets/snapshot.ts`): на iOS — в общий App Group `group.app.stopscroll.mobile`, на
Android — в AsyncStorage для фоновой задачи виджета. В полночь виджеты сами переходят на новый день.

## Как считается «спасённое время»

Каждая победа над импульсом (SOS-пауза или выполненная замена) начисляет длину одной «сессии» в ленте
из настроек (по умолчанию 15 минут). Сумма побед — в конвертере: 1 книга ≈ 5 часов чтения,
прогулка — 30 минут, тренировка — 45 и т. д. (`src/utils/catalog.ts → EQUIVALENTS`).

День считается **под контролем**, если отмеченное время в ленте не превышает дневной лимит.
Неотмеченный «сегодня» не обрывает серию до конца дня.

## Монетизация (RevenueCat)

1. Создайте проект в RevenueCat, подключите приложения App Store и Google Play.
2. Заведите entitlement **`pro`** и offering с пакетами (например, `$rc_annual`, `$rc_monthly`,
   `$rc_lifetime`) — они появятся на Paywall автоматически, порядок и подписи берутся из типа пакета.
3. Пропишите ключи в `.env.local` (для EAS — в переменных окружения проекта):

| Переменная | Где используется |
|---|---|
| `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` | dev/store-сборка iOS (`appl_…`) |
| `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` | dev/store-сборка Android (`goog_…`) |
| `EXPO_PUBLIC_REVENUECAT_TEST_API_KEY` | Expo Go и веб — RevenueCat Test Store (`test_…`) |
| `EXPO_PUBLIC_REVENUECAT_ENTITLEMENT_ID` | идентификатор entitlement, по умолчанию `pro` |
| `EXPO_PUBLIC_TERMS_URL` | «Условия использования» на Paywall и в Настройках; пусто — стандартное EULA Apple на iOS (на Android ссылка скрыта) |
| `EXPO_PUBLIC_PRIVACY_URL` | «Политика конфиденциальности»; пусто — встроенный экран политики |
| `EXPO_PUBLIC_AI_URL` | адрес `server/ai-coach`; пусто — AI-анализ выключен |
| `EXPO_PUBLIC_AI_TOKEN` | необязательный общий токен для этого сервера (не секрет: он виден в сборке) |

Без ключей приложение полностью работает в бесплатном режиме, а Paywall сообщает, что покупки
недоступны. В dev-сборке (`__DEV__`) в Настройках есть переключатель **«Тестовый Pro»**, чтобы
проверять платные функции без магазина.

На iOS пометка «N дней бесплатно» показывается только тем, кому магазин действительно даст пробный
период (`checkTrialOrIntroductoryPriceEligibility`). Для Android подключён config-плагин
`plugins/withSingleTopActivity.js` (`launchMode="singleTop"`): с режимом Expo по умолчанию
возврат в приложение во время оплаты (например, после 3-D Secure) отменял бы покупку.

Реальные покупки App Store / Google Play требуют нативной сборки (в Expo Go SDK работает в режиме
браузера с Test Store):

```bash
npx eas-cli@latest build --profile preview --platform android   # APK для внутреннего теста
npx eas-cli@latest build --profile production --platform ios
```

Что открывает Pro (`src/utils/pro.ts`):

| | Free | Pro |
|---|---|---|
| SOS-пауза 15 секунд | ✓ | ✓ |
| Упражнения для паузы | 1 | 4 |
| Микро-замены | 12 | 20 + свои |
| Динамика скроллинга | 7 дней | 30 дней |
| Тепловая карта | 6 недель | 16 недель |
| Эквиваленты времени | 3 | 6 |
| Паттерны по часам и дням недели | — | ✓ |

## Состояние и хранение

`AppContext` — единый источник данных. Состояние загружается из AsyncStorage при старте
(ключ `@stopscroll/state/v1`) и сохраняется после каждого изменения. Если хранилище не удалось
прочитать (после повторной попытки), сохранение в этой сессии отключается, чтобы пустое состояние
не затёрло настоящую историю. Загруженные данные проходят
валидацию (`src/utils/persistedState.ts`): битые поля заменяются значениями по умолчанию, а
нечитаемый JSON сохраняется в резервный ключ `@stopscroll/state/v1:corrupt`.

| Поле | Назначение |
|---|---|
| `settings` | дневной лимит, длина сессии, исходный уровень, главная лента, напоминание об отчёте, живые формулировки |
| `scrollLog` | минуты в ленте по дням (`YYYY-MM-DD → минуты`) |
| `wins` | последние 2000 побед: `{ timestamp, minutesSaved, source: "sos" \| "replacement", trigger?, replacementId? }` |
| `winArchive` | итоги побед, вытесненных из списка (количество, минуты, замены) — «всего» никогда не уменьшается |
| `slips` | срывы: `{ timestamp, trigger, app, minutesLost, note }`; `trigger` — ответ на «Что произошло?» (`null`, пока срыв не разобран) |
| `coachLog` | память коуча, до 120 дней: `{ day, risk, advice }` — какой совет был в какой день |

AI-коуч хранит свои данные отдельно: `@stopscroll/ai/v1` — согласие, память ChatGPT, аналитика,
прогноз, вопрос, ответы, эксперименты; `@stopscroll/ai/entries/ГГГГ-ММ` — записи месяца с разбором.
| `achievements` | id достижения → дата получения (у старых установок проставляется по истории, без анимаций) |
| `lastSeenReport` | понедельник последнего открытого недельного отчёта (метка «Новый») |
| `customReplacements` | свои замены (Pro) |
| `lastExerciseId`, `themePreference`, `onboarded` | последнее упражнение SOS, тема, онбординг |

## Перед публикацией

- Добавьте в `app.json` свой `ios.appleTeamId` — без него Xcode не подпишет цель виджета.
  App Group `group.app.stopscroll.mobile` создаётся EAS Build автоматически.
- Если подключаете живые формулировки, укажите в App Store / Google Play, что приложение отправляет
  на ваш сервер тексты советов (без идентификаторов и записей), и задайте в Cloudflare лимит запросов.

- Замените идентификаторы `app.stopscroll.mobile` в `app.json` на свои.
- Иконки в `assets/` — фирменный знак: белая «пауза» на синем градиенте (иконка iOS, адаптивная иконка Android, сплэш, favicon).
- Укажите `EXPO_PUBLIC_PRIVACY_URL` (страница политики нужна и в App Store Connect / Google Play
  Console) или проверьте текст встроенного экрана `src/screens/PrivacyScreen.tsx`.
- Сплэш-экран настроен через `expo-splash-screen` (светлый и тёмный фон).
