# StopScroll

Персональный коуч по цифровым привычкам. StopScroll каждый день разбирает записи пользователя —
время в ленте, срывы и их причины, SOS-паузы и замены — находит закономерности (часы, дни недели,
причины, что помогает) и превращает их в спокойный утренний брифинг: риск бесконтрольного скролла
на сегодня, почему он такой и один конкретный совет. После срыва коуч коротко спрашивает, что
произошло, а по воскресеньям пишет разбор недели. Все выводы — только из реальных данных
пользователя; данные хранятся локально на устройстве, монетизация — через RevenueCat.

Проект собран на архитектуре шаблона [CleanStart](https://github.com/rdzabbarov2002-gif/Clean):
тот же стек, контекст + чистый редьюсер, валидация сохранённого состояния, NativeWind-компоненты.

**Стек:** Expo SDK 57 (managed, Continuous Native Generation) · React Native 0.86 · TypeScript ·
NativeWind 4 (Tailwind CSS 3) · React Navigation 7 (native stack + bottom tabs) · AsyncStorage ·
react-native-svg · `@react-native-community/slider` · RevenueCat (`react-native-purchases`) ·
`expo-notifications` · виджеты iOS через `@bacons/apple-targets` (WidgetKit) · виджеты Android
через `react-native-android-widget` · необязательный сервер формулировок коуча (`server/coach-voice`,
Cloudflare Worker + Anthropic API).

## Запуск

```bash
npm install
cp .env.example .env.local   # ключи RevenueCat (можно пропустить — см. ниже)
npm start                    # QR-код для Expo Go (без виджетов и уведомлений)
npx expo run:android         # нативная сборка Android (нужен Android SDK)
npx expo run:ios             # нативная сборка iOS (нужен macOS + Xcode 16)
npm run web                  # быстрый просмотр в браузере
```

Виджеты, уведомления и покупки работают только в нативной сборке (`npx expo run:*` или
`eas build --profile preview`): папки `ios/` и `android/` не хранятся в репозитории, их генерирует
`npx expo prebuild` из `app.json`, плагинов и `targets/`.

Проверки:

```bash
npm run typecheck  # tsc --noEmit
npm run lint       # ESLint (eslint-config-expo)
npm test           # Jest: коуч, редьюсер, хранилище, статистика, аналитика, отчёт, достижения, виджеты
```

## Персональный коуч

Коуч — это детерминированный анализ записей (`src/coach`), а не чат и не генератор случайных
советов. Каждый вывод опирается на конкретные числа из истории пользователя; если данных для
вывода не хватает, коуч его не делает.

- **Анализ** (`patterns.ts`, `history.ts`): последние 8 недель по дням — время в ленте, срывы
  (час, день недели, длительность, причина), победы и замены. Находит: час, после которого
  случается большинство срывов; главную причину (только среди срывов с указанной причиной);
  самый трудный и самый спокойный день недели; повторяющийся тяжёлый день («уже третья неделя
  подряд…»); помогают ли прогулки и замены (сравнение дней с ними и без); динамику времени в
  ленте, срывов, вечерней привычки и длины срывов; текущую и лучшую серию.
- **Брифинг дня** (`briefing.ts`): риск складывается из сигналов с весами (трудный день недели,
  срывы за последние три дня, превышение лимита вчера и сегодня, серия, динамика недели); причина —
  самый сильный сигнал, сформулированный из чисел. Пока записей меньше чем за 5 дней из последних
  28, риск не оценивается — коуч пишет, что собирает информацию.
- **Совет дня** (`advice.ts`): выбирается правилами по главной причине, рискованному часу и тому,
  что помогало; вчерашний совет, который сработал, получает бонус, не сработавший — штраф, один
  и тот же совет три дня подряд отдыхает. Случайности нет: от дня зависит только выбор одной из
  равноценных формулировок (стабильный хеш даты).
- **Память** (`coachLog` в состоянии): какой совет был в какой день и с каким риском; на
  следующий день коуч смотрит, сработал ли он (для вечерних советов — по вечеру), и говорит об этом.
- **Разбор недели** (`weeklyReview.ts`) и **ответ после срыва** (`reflection.ts`) строятся из тех же
  чисел. Голос коуча — на «ты», без указания пола, без восклицаний, упрёков и токсичного позитива.
  В интерфейсе он называется «Ваш персональный коуч»; технологии не упоминаются.

### Живые формулировки (необязательно)

Тексты коуча уже готовы на устройстве. Если задать `EXPO_PUBLIC_COACH_VOICE_URL`, готовые фразы
(без заметок, дат и самих записей) отправляются на собственный сервер `server/coach-voice`, где
Anthropic API (`claude-opus-5-5`, structured outputs) лишь делает их естественнее. Приложение
принимает новую формулировку, только если в ней те же числа, время и дни недели, нет восклицаний,
эмодзи и упоминаний технологий (`src/coach/phrasing.ts`); иначе остаётся исходный текст. Ответы
кешируются на устройстве, интерфейс никогда не ждёт сервер. Пользователь может выключить это в
Настройках → «Живые формулировки».

Ключ Anthropic нельзя класть в приложение: всё, что попадает в сборку (в том числе `EXPO_PUBLIC_*`),
можно извлечь. Поэтому ключ хранится как секрет Worker'а:

```bash
cd server/coach-voice
npm install
npx wrangler@4 secret put ANTHROPIC_API_KEY
npx wrangler@4 secret put APP_TOKEN        # необязательно; то же значение — в EXPO_PUBLIC_COACH_VOICE_TOKEN
npm run deploy                             # URL Worker'а → EXPO_PUBLIC_COACH_VOICE_URL
npm run typecheck                          # проверка типов сервера
```

Без сервера коуч работает полностью: все выводы, советы и разборы строятся на устройстве.

## Виджеты

Пять виджетов на iOS (`targets/widget`, SwiftUI/WidgetKit) и Android (`src/widgets`,
`react-native-android-widget`): «Сегодня» (спасено), «Серия», «Лимит» (сколько осталось),
«Прогресс дня» (кольцо) и «Полезная замена» (меняется каждые полчаса). На iOS «Сегодня», «Лимит»,
«Серия» и кольцо есть и для экрана блокировки. Приложение пишет снимок реальных цифр
(`src/widgets/snapshot.ts`): на iOS — в общий App Group `group.app.stopscroll.mobile`, на
Android — в AsyncStorage для фоновой задачи виджета. В полночь виджеты сами переходят на новый день.

## Как считается «спасённое время»

Каждая победа над импульсом (SOS-пауза или выполненная замена) начисляет длину одной «сессии» в ленте
из настроек (по умолчанию 15 минут). Сумма побед — в конвертере: 1 книга ≈ 5 часов чтения,
прогулка — 30 минут, тренировка — 45 и т. д. (`src/utils/catalog.ts → EQUIVALENTS`).

День считается **под контролем**, если отмеченное время в ленте не превышает дневной лимит.
Неотмеченный «сегодня» не обрывает серию до конца дня.

## Монетизация (RevenueCat)

1. Создайте проект в RevenueCat, подключите приложения App Store и Google Play.
2. Заведите entitlement **`pro`** и offering с пакетами (например, `$rc_annual`, `$rc_monthly`,
   `$rc_lifetime`) — они появятся на Paywall автоматически, порядок и подписи берутся из типа пакета.
3. Пропишите ключи в `.env.local` (для EAS — в переменных окружения проекта):

| Переменная | Где используется |
|---|---|
| `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` | dev/store-сборка iOS (`appl_…`) |
| `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` | dev/store-сборка Android (`goog_…`) |
| `EXPO_PUBLIC_REVENUECAT_TEST_API_KEY` | Expo Go и веб — RevenueCat Test Store (`test_…`) |
| `EXPO_PUBLIC_REVENUECAT_ENTITLEMENT_ID` | идентификатор entitlement, по умолчанию `pro` |
| `EXPO_PUBLIC_TERMS_URL` | «Условия использования» на Paywall и в Настройках; пусто — стандартное EULA Apple на iOS (на Android ссылка скрыта) |
| `EXPO_PUBLIC_PRIVACY_URL` | «Политика конфиденциальности»; пусто — встроенный экран политики |
| `EXPO_PUBLIC_COACH_VOICE_URL` | адрес `server/coach-voice` для живых формулировок; пусто — выключено |
| `EXPO_PUBLIC_COACH_VOICE_TOKEN` | необязательный общий токен для этого сервера (не секрет: он виден в сборке) |

Без ключей приложение полностью работает в бесплатном режиме, а Paywall сообщает, что покупки
недоступны. В dev-сборке (`__DEV__`) в Настройках есть переключатель **«Тестовый Pro»**, чтобы
проверять платные функции без магазина.

На iOS пометка «N дней бесплатно» показывается только тем, кому магазин действительно даст пробный
период (`checkTrialOrIntroductoryPriceEligibility`). Для Android подключён config-плагин
`plugins/withSingleTopActivity.js` (`launchMode="singleTop"`): с режимом Expo по умолчанию
возврат в приложение во время оплаты (например, после 3-D Secure) отменял бы покупку.

Реальные покупки App Store / Google Play требуют нативной сборки (в Expo Go SDK работает в режиме
браузера с Test Store):

```bash
npx eas-cli@latest build --profile preview --platform android   # APK для внутреннего теста
npx eas-cli@latest build --profile production --platform ios
```

Что открывает Pro (`src/utils/pro.ts`):

| | Free | Pro |
|---|---|---|
| SOS-пауза 15 секунд | ✓ | ✓ |
| Упражнения для паузы | 1 | 4 |
| Микро-замены | 12 | 20 + свои |
| Динамика скроллинга | 7 дней | 30 дней |
| Тепловая карта | 6 недель | 16 недель |
| Эквиваленты времени | 3 | 6 |
| Паттерны по часам и дням недели | — | ✓ |

## Состояние и хранение

`AppContext` — единый источник данных. Состояние загружается из AsyncStorage при старте
(ключ `@stopscroll/state/v1`) и сохраняется после каждого изменения. Если хранилище не удалось
прочитать (после повторной попытки), сохранение в этой сессии отключается, чтобы пустое состояние
не затёрло настоящую историю. Загруженные данные проходят
валидацию (`src/utils/persistedState.ts`): битые поля заменяются значениями по умолчанию, а
нечитаемый JSON сохраняется в резервный ключ `@stopscroll/state/v1:corrupt`.

| Поле | Назначение |
|---|---|
| `settings` | дневной лимит, длина сессии, исходный уровень, главная лента, напоминание об отчёте, живые формулировки |
| `scrollLog` | минуты в ленте по дням (`YYYY-MM-DD → минуты`) |
| `wins` | последние 2000 побед: `{ timestamp, minutesSaved, source: "sos" \| "replacement", trigger?, replacementId? }` |
| `winArchive` | итоги побед, вытесненных из списка (количество, минуты, замены) — «всего» никогда не уменьшается |
| `slips` | срывы: `{ timestamp, trigger, app, minutesLost, note }`; `trigger` — ответ на «Что произошло?» (`null`, пока срыв не разобран) |
| `coachLog` | память коуча, до 120 дней: `{ day, risk, advice }` — какой совет был в какой день |
| `achievements` | id достижения → дата получения (у старых установок проставляется по истории, без анимаций) |
| `lastSeenReport` | понедельник последнего открытого недельного отчёта (метка «Новый») |
| `customReplacements` | свои замены (Pro) |
| `lastExerciseId`, `themePreference`, `onboarded` | последнее упражнение SOS, тема, онбординг |

## Перед публикацией

- Добавьте в `app.json` свой `ios.appleTeamId` — без него Xcode не подпишет цель виджета.
  App Group `group.app.stopscroll.mobile` создаётся EAS Build автоматически.
- Если подключаете живые формулировки, укажите в App Store / Google Play, что приложение отправляет
  на ваш сервер тексты советов (без идентификаторов и записей), и задайте в Cloudflare лимит запросов.

- Замените идентификаторы `app.stopscroll.mobile` в `app.json` на свои.
- Иконки в `assets/` — фирменный знак: белая «пауза» на синем градиенте (иконка iOS, адаптивная иконка Android, сплэш, favicon).
- Укажите `EXPO_PUBLIC_PRIVACY_URL` (страница политики нужна и в App Store Connect / Google Play
  Console) или проверьте текст встроенного экрана `src/screens/PrivacyScreen.tsx`.
- Сплэш-экран настроен через `expo-splash-screen` (светлый и тёмный фон).
