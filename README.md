# StopScroll

Персональный AI-коуч по цифровым привычкам. Пользователь своими словами записывает, что произошло
перед тем, как захотелось открыть ленту, — ChatGPT разбирает каждую запись (причина, состояние,
ситуация, тип поведения), постепенно изучает всю историю, строит прогноз риска на сегодня,
замечает изменения, выдвигает осторожные гипотезы, изредка задаёт уточняющие вопросы и раз в
неделю предлагает маленький эксперимент. Всё это — на вкладке **AI**, без чата. Без подключённого
ChatGPT продолжает работать прежний коуч на устройстве. История хранится локально, монетизация —
через RevenueCat.

Проект собран на архитектуре шаблона [CleanStart](https://github.com/rdzabbarov2002-gif/Clean):
тот же стек, контекст + чистый редьюсер, валидация сохранённого состояния, NativeWind-компоненты.

**Стек:** Expo SDK 57 (managed, Continuous Native Generation) · React Native 0.86 · TypeScript ·
NativeWind 4 (Tailwind CSS 3) · React Navigation 7 (native stack + bottom tabs) · AsyncStorage ·
react-native-svg · `@react-native-community/slider` · RevenueCat (`react-native-purchases`) ·
`expo-notifications` · виджеты iOS через `@bacons/apple-targets` (WidgetKit) · виджеты Android
через `react-native-android-widget` · сервер AI-коуча `server/ai-coach` (Cloudflare Worker +
официальный SDK `openai`, Responses API со Structured Outputs).

## Запуск

```bash
npm install
cp .env.example .env.local   # ключи RevenueCat (можно пропустить — см. ниже)
npm start                    # QR-код для Expo Go (без виджетов и уведомлений)
npx expo run:android         # нативная сборка Android (нужен Android SDK)
npx expo run:ios             # нативная сборка iOS (нужен macOS + Xcode 16)
npm run web                  # быстрый просмотр в браузере
```

Виджеты, уведомления и покупки работают только в нативной сборке (`npx expo run:*` или
`eas build --profile preview`): папки `ios/` и `android/` не хранятся в репозитории, их генерирует
`npx expo prebuild` из `app.json`, плагинов и `targets/`.

**Без компьютера, только с телефона:**

1. Сервер AI-коуча: в Cloudflare → Workers & Pages → Create application → Import a repository →
   StopScroll; Deploy command `npx wrangler deploy`, Advanced settings → Path `/server/ai-coach`.
   Cloudflare сам выпускает сервер из репозитория. Ключ — в Worker → Settings → Variables and
   Secrets → `OPENAI_API_KEY` с галочкой Secret (в GitHub ключ не нужен). Адрес сервера — в
   переменную репозитория `AI_URL`; проверка: Actions → **Check AI server** → Run workflow
   (запросы приложения на русском и английском, несколько центов).
2. Приложение в Expo Go: секрет `EXPO_TOKEN` (expo.dev → Access tokens), затем Actions →
   **Expo Go update** → Run workflow. В Expo Go войдите в тот же аккаунт Expo — StopScroll
   появится на главной (ветка `expo-go`). Дальше обновление публикуется при каждом изменении
   приложения.

В Expo Go AI-коуч работает, если в `.env.local` задан `EXPO_PUBLIC_AI_URL` (адрес развёрнутого
`server/ai-coach`, см. ниже); без него приложение работает без AI-анализа. Еженедельное напоминание
в Expo Go на Android недоступно (Expo Go не поддерживает уведомления с SDK 53): кнопка включения
ничего не делает, остальное приложение не затронуто.

Проверки:

```bash
npm run typecheck  # tsc --noEmit
npm run lint       # ESLint (eslint-config-expo)
npm test           # Jest: коуч, редьюсер, хранилище, статистика, аналитика, отчёт, достижения, виджеты
npx jest src/__tests__/app.e2e.test.tsx --preset jest-expo/android  # всё приложение как Android
```

## Дизайн

Стиль приложения «Здоровье» от Apple: белая (или чёрная в тёмной теме) страница, мягкие серые
карточки с цветной подписью и одной фразой-выводом, крупные округлые цифры (SF Pro Rounded на iOS),
системные цвета iOS. Внизу — плавающее меню-«пилюля» и отдельная круглая синяя кнопка паузы (SOS),
которая открывает паузу с любого экрана. Тема — светлая, тёмная или как в системе (Настройки).

## Языки

- При первом запуске пользователь обязательно выбирает язык: Русский или English. Выбор
  сохраняется; сменить его можно в Настройках → Язык.
- Тексты интерфейса — в `src/i18n/messages/<область>/<язык>.ts`. `ru.ts` — источник истины,
  `en.ts` типизирован его типом: пропущенный ключ или другой набор параметров — ошибка
  TypeScript, а `src/i18n/__tests__` проверяет полноту каталогов. В компонентах — `useT()`, вне
  React — `m()` (вызывать во время работы, не при импорте модуля).
- Числа, даты и множественное число — по правилам языка (`src/i18n/plural.ts`, `src/utils/date.ts`).
- Язык уходит в каждый запрос к ChatGPT (`language`), и всё, что пишет модель, — разборы, выводы,
  вопросы, советы, эксперименты — пишется на нём. Инструкции модели — на английском (один текст на
  оба языка); язык ответа и форма обращения задаются в их конце.
- После смены языка память коуча один раз переводится (`/translate`); разборы прошлых записей
  остаются такими, какими пользователь их видел.
- Как добавить язык: код в `src/i18n/languages.ts`, правило множественного числа в `plural.ts`,
  файл `<код>.ts` в каждой папке `src/i18n/messages/*` (TypeScript покажет, чего не хватает),
  строки виджета iOS в `targets/widget`, название и обращение в `server/ai-coach/src/prompts.ts`.

## AI-коуч (ChatGPT)

### Как это устроено

```text
новая запись    → /entry (лёгкая модель: разбор записи, одна строка для памяти, голоса за убеждения)
раз в неделю    → проверка без памяти (/entry, до 6 старых записей) → /deep (сильная модель:
                  перечитывает спорные оригиналы, меняет память операциями, вопросы, эксперимент)
смена языка     → /translate (один раз: память коуча на новом языке)
всё остальное — на телефоне, без запросов: прогноз на сегодня, цифры аналитики, итог эксперимента
```

Подробный разбор устройства памяти, сравнение вариантов, стоимость и риски —
[`docs/ai-memory.md`](docs/ai-memory.md).

- **ChatGPT — только там, где он видит то, чего не видно в цифрах.** Он читает запись своими
  словами пользователя (причина, состояние, ситуация, тип поведения, теги, уверенность 40/70/95) и
  ищет закономерности, которые человек сам не замечает. Очевидного он не пишет: поле «объяснение»
  появляется, только если есть неочевидная связь с памятью или с похожим прошлым эпизодом.
- **Арифметика — на телефоне** (`src/ai/facts.ts`, `analytics.ts`, `forecast.ts`): серии, рекорды,
  дни и часы, среднее время в ленте, доли причин, тренды, сравнение с прошлым месяцем и годом,
  сэкономленное время, итог эксперимента «до / во время». Точнее, мгновенно и бесплатно.
- **Прогноз на сегодня** считается на телефоне после каждой записи: эмпирическая частота «лента
  побеждала с этого часа до конца дня» по последним 4 неделям и по тому же дню недели, с поправками.
  Опасные периоды и личные советы в нём — из памяти ChatGPT; совет, который не помог в эксперименте,
  больше не предлагается, а помогший идёт первым.
- **Два слоя у записи.** `analysis` — разбор, который пользователь увидел в тот день; он не
  меняется никогда. `reading` — текущее понимание записи коучем: с него считается аналитика, и
  только его может пересмотреть глубокий анализ, перечитав оригинал. Новые выводы видны в
  «Долгой памяти», «Что меняется» и в разделах аналитики, история записей не переписывается.
- **Долгосрочная память** (`AiMemory`, `src/ai/memory.ts`) — единственное, что ChatGPT «помнит»:
  портрет, вывод, эмоции, сильные и слабые стороны, изменения, события и **убеждения** — гипотезы,
  причины-ситуации, опасные периоды и советы со стабильными id, статусом (предположение →
  подтверждено → устойчиво; ослаблено, опровергнуто, заменено), сроком («так было в марте–мае»),
  историей формулировок и доказательствами. Глубокий анализ не переписывает память целиком, а
  присылает операции (добавить, уточнить, подтвердить, ослабить, опровергнуть, заменить, ограничить
  сроком); всё, что не упомянуто, остаётся. Плюс журнал собственных исправлений коуча («раньше
  казалось… теперь точнее…»), главы по месяцам и таблица по годам.
- **Доказательства считаются на телефоне** (`src/ai/evidence.ts`). Голос первого разбора записи —
  слабое доказательство: лёгкая модель видела память и может её просто повторять. Сильное
  («независимое») — то, что память сама произвести не может: прочтение, подтверждённое без памяти
  или перечитанное глубоким анализом, ответ пользователя на вопрос (×2), итог эксперимента и
  арифметика записей (опасный период реален, только если трудные моменты действительно чаще в нём).
  Приложение повышает статус только с независимыми доказательствами, сильное убеждение снимает в два
  шага, «мигающее» замораживает до ответа пользователя, не даёт вернуть опровергнутое без новых
  данных и ограничивает число изменений за раз. Каждый отказ уходит в следующий анализ с причиной.
- **Перечитывание оригиналов** (`src/ai/review.ts`). Перед глубоким анализом приложение выбирает до
  6 старых записей, где второй взгляд может изменить картину: противоречащую самому сильному
  убеждению, неуверенные, решающие для открытого убеждения, основу сильнейшего убеждения раз в
  90 дней, контрольную уверенную (каждый второй раз) — и лёгкая модель читает их **без памяти**.
  Совпало — прочтение подтверждено независимо, больше ничего не тратится. Разошлось — оригинал и оба
  прочтения уходят в `/deep` (до 4 таких и одна запись перед переломом в поведении), и он решает:
  оставить или пересмотреть. Возврат к уже оставленному прочтению помечает запись спорной — её больше
  не перечитывают. Удалённые записи не перечитываются никогда.
- **Калибровка уверенности.** Проверки без памяти показывают, как часто «уверенный» первый разбор
  на самом деле расходится со вторым; после 8 проверок неуверенными считаются по факту, а не по
  заявленной цифре.
- **Текст записи уходит один раз** — в `/entry` (и, только если выбрана для перепроверки, ещё раз).
  Дальше путешествует только её суть в одну строку (`gist`). `/deep` получает память, новые записи
  строками, несколько выбранных оригиналов, ответы, удалённые записи и компактные таблицы по всей
  истории — объём не растёт с длиной истории.
- **Эпизодическая память.** К новой записи приложение подбирает до двух похожих прошлых эпизодов
  (дата, чем закончилось, суть) — ChatGPT может сказать «так уже было 3 сентября, и тогда помогла
  прогулка».
- **Расписание** (`src/ai/schedule.ts`): запись — сразу (накопившиеся офлайн — одним запросом, до 5);
  та же запись слово в слово в пределах 30 дней — без запроса. Глубокий анализ: первый — как только
  есть история, второй — на следующий день (если появилось 3+ записи), первые две недели — раз в
  3 дня, потом раз в неделю или раньше, если накопилось 35+ записей (не чаще раза в 3 дня); без новых
  данных — никогда. Вопросы — по одному, не чаще раза в 3 дня; эксперимент — не чаще раза в 6 дней.
- **Ответы проверяются** (`src/ai/parse.ts`, `memory.ts`): структура, размеры и правила
  доказательств; битый ответ не попадает ни на экран, ни в память.
- **Хранение** (`src/ai/storage.ts`): отдельно от основного состояния, записи — по месяцам в своих
  ключах AsyncStorage, история не обрезается. Данные прежних версий коуча читаются и переводятся в
  новый формат: старые гипотезы, причины, периоды и советы становятся убеждениями, а их счёт голосов
  — стартовыми доказательствами.
- **Удаление.** Удалённая запись исчезает с телефона и из ссылок памяти; если память её уже вобрала,
  в следующий анализ уходит только пометка «удалена» (без текста). Сброс или выключение во время
  запроса отбрасывает ответ.
- **Ошибки.** Один запрос за раз; повтор через 1–2 минуты. Нет сети, тайм-аут или перегрузка не
  тратят попытки, битый ответ или ошибка сервера — тратят (после трёх запись ждёт «Повторить»).
- **Разрешение.** До явного согласия ничего не отправляется (App Store 5.1.2(i), GDPR); выключить и
  стереть данные коуча можно в Настройках.
- **Без ChatGPT** записи сохраняются и ждут, а на главной работает коуч на устройстве (`src/coach`).
  В веб-демо без сервера вкладка AI показывает **помеченный** образец экрана.

### Сервер `server/ai-coach`

Ключ OpenAI нельзя класть в приложение: всё, что попадает в сборку (в том числе `EXPO_PUBLIC_*`),
можно извлечь. Поэтому между приложением и OpenAI стоит Cloudflare Worker. Он ничего не хранит
(`store: false`, без базы): память и история приходят с телефона в каждом запросе.

```bash
cd server/ai-coach
npm install
npx wrangler@4 secret put OPENAI_API_KEY
npx wrangler@4 secret put APP_TOKEN        # необязательно; то же значение — в EXPO_PUBLIC_AI_TOKEN
npm run deploy                             # URL Worker'а → EXPO_PUBLIC_AI_URL
npm run typecheck
```

Две модели: `OPENAI_MODEL_LIGHT` для частых простых запросов (`/entry`, `/phrase`, `/translate`; по умолчанию
`gpt-5.4-nano`) и `OPENAI_MODEL_DEEP` для редкого глубокого анализа (по умолчанию `gpt-5.4-mini`);
глубина рассуждений — `OPENAI_EFFORT_LIGHT` (`low`) и `OPENAI_EFFORT_DEEP` (`medium`). Ответы короткие
(`verbosity: low`, длина списков ограничена схемой), неизменная часть запроса (инструкции и схема)
идёт первой и с `prompt_cache_key`, чтобы OpenAI брал её из кэша по сниженной цене. Каждый запрос
пишет в лог Worker расход токенов (без данных пользователя): `wrangler tail` показывает реальную цену.
**Перед публикацией включите лимиты** в `wrangler.toml` (Workers Rate Limiting): `RATE_LIMITER` —
по IP (обойти, подменив заголовок, нельзя) и при желании `INSTALL_RATE_LIMITER` — по установке; и
задайте месячный бюджет проекта в кабинете OpenAI. `APP_TOKEN` защищает только от случайного
трафика: он виден в сборке приложения. Тело запроса ограничено по байтам до чтения. Коды ответов:
502 — непригодный ответ модели, 503/504/429 — временная недоступность (приложение ждёт и
повторяет), 500 — ошибка настройки (ключ, модель); подробности — в логах Worker (`wrangler tail`). Для веб-превью задайте переменные репозитория `AI_URL` и
`AI_TOKEN` (Settings → Secrets and variables → Actions → Variables).

**Стоимость (оценка, цены OpenAI на октябрь 2026).** Активный пользователь (5 записей в день):
5 × `/entry` (~1,25 тыс. входных токенов, ~0,4 тыс. выходных с рассуждением) ≈ $0,0039 в день, плюс
раз в неделю проверка без памяти (~$0,003) и `/deep` (~6,5 тыс. входных, ~6 тыс. выходных с
рассуждением, ≈ $0,031) ≈ $0,0048 в день. Итого **≈ $0,009 в день, ≈ $0,26 в месяц** — столько же,
сколько до перечитывания (порог досрочного анализа поднят с 25 до 35 записей; у пользователя с
3 записями в день — ≈ $0,007 в день). Смена языка — разовый `/translate`, около $0,01. Число
токенов рассуждения — оценка; точный расход виден в логах Worker (`wrangler tail`). Разбор записи —
несколько секунд, глубокий анализ — до 10–30 секунд; интерфейс не ждёт.

### Живые формулировки

Прежний коуч на устройстве может отдавать свои готовые фразы (без заметок и записей) на `/phrase`,
где ChatGPT делает их естественнее; приложение принимает новую формулировку, только если в ней те же
числа, время и дни недели (`src/coach/phrasing.ts`). Работает при подключённом сервере и разрешении;
по умолчанию выключено (заметной пользы меньше, чем стоят запросы) — включается в Настройках.

### Прежний коуч на устройстве

`src/coach` — детерминированный разбор последних 8 недель (брифинг дня, советы, разбор недели,
ответ после срыва в Дневнике). Он остаётся как часть приложения: на главной он виден, пока
ChatGPT не подключён, а разбор недели и ответ после срыва работают всегда.

## Виджеты

Пять виджетов на iOS (`targets/widget`, SwiftUI/WidgetKit) и Android (`src/widgets`,
`react-native-android-widget`): «Сегодня» (спасено), «Серия», «Лимит» (сколько осталось),
«Прогресс дня» (кольцо) и «Полезная замена» (меняется каждые полчаса). На iOS «Сегодня», «Лимит»,
«Серия» и кольцо есть и для экрана блокировки. Приложение пишет снимок реальных цифр
(`src/widgets/snapshot.ts`): на iOS — в общий App Group `group.app.stopscroll.mobile`, на
Android — в AsyncStorage для фоновой задачи виджета. В полночь виджеты сами переходят на новый день.

## Как считается «спасённое время»

Каждая победа над импульсом (SOS-пауза или выполненная замена) начисляет длину одной «сессии» в ленте
из настроек (по умолчанию 15 минут). Сумма побед — в конвертере: 1 книга ≈ 5 часов чтения,
прогулка — 30 минут, тренировка — 45 и т. д. (`src/utils/catalog.ts → EQUIVALENTS`).

День считается **под контролем**, если отмеченное время в ленте не превышает дневной лимит.
Неотмеченный «сегодня» не обрывает серию до конца дня.

## Монетизация (RevenueCat)

1. Создайте проект в RevenueCat, подключите приложения App Store и Google Play.
2. Заведите entitlement **`pro`** и offering с пакетами (например, `$rc_annual`, `$rc_monthly`,
   `$rc_lifetime`) — они появятся на Paywall автоматически, порядок и подписи берутся из типа пакета.
3. Пропишите ключи в `.env.local` (для EAS — в переменных окружения проекта):

| Переменная | Где используется |
|---|---|
| `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` | dev/store-сборка iOS (`appl_…`) |
| `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` | dev/store-сборка Android (`goog_…`) |
| `EXPO_PUBLIC_REVENUECAT_TEST_API_KEY` | Expo Go и веб — RevenueCat Test Store (`test_…`) |
| `EXPO_PUBLIC_REVENUECAT_ENTITLEMENT_ID` | идентификатор entitlement, по умолчанию `pro` |
| `EXPO_PUBLIC_TERMS_URL` | «Условия использования» на Paywall и в Настройках; пусто — стандартное EULA Apple на iOS (на Android ссылка скрыта) |
| `EXPO_PUBLIC_PRIVACY_URL` | «Политика конфиденциальности»; пусто — встроенный экран политики |
| `EXPO_PUBLIC_AI_URL` | адрес `server/ai-coach`; пусто — AI-анализ выключен |
| `EXPO_PUBLIC_AI_TOKEN` | необязательный общий токен для этого сервера (не секрет: он виден в сборке) |

Без ключей приложение полностью работает в бесплатном режиме, а Paywall сообщает, что покупки
недоступны. В dev-сборке (`__DEV__`) в Настройках есть переключатель **«Тестовый Pro»**, чтобы
проверять платные функции без магазина.

На iOS пометка «N дней бесплатно» показывается только тем, кому магазин действительно даст пробный
период (`checkTrialOrIntroductoryPriceEligibility`). Для Android подключён config-плагин
`plugins/withSingleTopActivity.js` (`launchMode="singleTop"`): с режимом Expo по умолчанию
возврат в приложение во время оплаты (например, после 3-D Secure) отменял бы покупку.

Реальные покупки App Store / Google Play требуют нативной сборки (в Expo Go SDK работает в режиме
браузера с Test Store):

```bash
npx eas-cli@latest build --profile preview --platform android   # APK для внутреннего теста
npx eas-cli@latest build --profile production --platform ios
```

Что открывает Pro (`src/utils/pro.ts`):

| | Free | Pro |
|---|---|---|
| SOS-пауза 15 секунд | ✓ | ✓ |
| Упражнения для паузы | 1 | 4 |
| Микро-замены | 12 | 20 + свои |
| Динамика скроллинга | 7 дней | 30 дней |
| Тепловая карта | 6 недель | 16 недель |
| Эквиваленты времени | 3 | 6 |
| Паттерны по часам и дням недели | — | ✓ |

## Состояние и хранение

`AppContext` — единый источник данных. Состояние загружается из AsyncStorage при старте
(ключ `@stopscroll/state/v1`) и сохраняется после каждого изменения. Если хранилище не удалось
прочитать (после повторной попытки), сохранение в этой сессии отключается, чтобы пустое состояние
не затёрло настоящую историю. Загруженные данные проходят
валидацию (`src/utils/persistedState.ts`): битые поля заменяются значениями по умолчанию, а
нечитаемый JSON сохраняется в резервный ключ `@stopscroll/state/v1:corrupt`.

| Поле | Назначение |
|---|---|
| `settings` | дневной лимит, длина сессии, исходный уровень, главная лента, напоминание об отчёте, живые формулировки |
| `scrollLog` | минуты в ленте по дням (`YYYY-MM-DD → минуты`) |
| `wins` | последние 2000 побед: `{ timestamp, minutesSaved, source: "sos" \| "replacement", trigger?, replacementId? }` |
| `winArchive` | итоги побед, вытесненных из списка (количество, минуты, замены) — «всего» никогда не уменьшается |
| `slips` | срывы: `{ timestamp, trigger, app, minutesLost, note }`; `trigger` — ответ на «Что произошло?» (`null`, пока срыв не разобран) |
| `coachLog` | память коуча, до 120 дней: `{ day, risk, advice }` — какой совет был в какой день |

| `achievements` | id достижения → дата получения (у старых установок проставляется по истории, без анимаций) |
| `lastSeenReport` | понедельник последнего открытого недельного отчёта (метка «Новый») |
| `customReplacements` | свои замены (Pro) |
| `lastExerciseId`, `themePreference`, `onboarded` | последнее упражнение SOS, тема, онбординг |
| `language` | язык приложения (`null` — ещё не выбран: показывается выбор языка) |

AI-коуч хранит свои данные отдельно: `@stopscroll/ai/v1` — согласие, память ChatGPT (убеждения,
журнал исправлений, главы), язык памяти, калибровка уверенности, очередь вопросов, ответы,
эксперименты; `@stopscroll/ai/entries/ГГГГ-ММ` — записи месяца с разбором дня и текущим
прочтением. Аналитика и прогноз не хранятся — они пересчитываются на телефоне.

## Перед публикацией

- Добавьте в `app.json` свой `ios.appleTeamId` — без него Xcode не подпишет цель виджета.
  App Group `group.app.stopscroll.mobile` создаётся EAS Build автоматически.
- Если подключаете живые формулировки, укажите в App Store / Google Play, что приложение отправляет
  на ваш сервер тексты советов (без идентификаторов и записей), и задайте в Cloudflare лимит запросов.

- Замените идентификаторы `app.stopscroll.mobile` в `app.json` на свои.
- Иконки в `assets/` — фирменный знак: белая «пауза» на синем градиенте (иконка iOS, адаптивная иконка Android, сплэш, favicon).
- Укажите `EXPO_PUBLIC_PRIVACY_URL` (страница политики нужна и в App Store Connect / Google Play
  Console) или проверьте текст встроенного экрана `src/screens/PrivacyScreen.tsx`.
- Сплэш-экран настроен через `expo-splash-screen` (светлый и тёмный фон).
